# Charter homepage clone

A local clone of the https://www.charterlabs.io/ homepage, built with React 18, Vite 5, Tailwind v3, framer-motion, Lenis and Embla. It is for local reference only. The brand, copy, product imagery and partner logos belong to Charter Labs.

```bash
npm install
npm run dev   # http://localhost:5190
```

## Information architecture

| File | Edit by hand? |
|---|---|
| `ia.json` | **Yes, this is the only file to edit.** |
| `IA.md` | No, generated by `build.mjs` |
| `matrix.csv` | No, generated by `build.mjs` |

After changing `ia.json`, rerun:

```bash
node validate.mjs && node build.mjs
```

### What the data shows

- **One route, one template.** There is one built route (`/`) and one template. It has 12 sections in render order: header, 10 content blocks and footer. Every section is used once, so the section × template matrix has nothing to share yet. All 12 are page-local until a second template exists.
- **Linked routes that aren't built.** The nav and footer link to `/contact` and `/legal/privacy-policy`, but neither page exists in this clone. They are listed in `meta.linkedUnbuiltRoutes` rather than invented as templates.
- **Reuse happens in the motion primitives in `src/components/motion/`, not in sections.**
  - `Reveal` is used in 9 section components.
  - `Mirror` (reflections) is used in 6: Header, Intro, Send, Overview, Earn and Payroll.
  - `Handoff` wraps 3 sections: Hero, Logo and Security.
  - Any new page should be built from these primitives.
- **Tone split.** The page splits into a light half and an inverse half at `transition.light-to-dark`. Header, hero, intro, logo and send are light. Overview, earn, payroll, security, FAQ and footer are inverse. Any added section has to respect that order.

## Waitlist endpoint

The original site posts the waitlist form to Charter's own form endpoint. This clone does not. `src/components/Waitlist.jsx` uses a local `fakeSubmit()` that makes no network request: it waits 600ms and then shows "Thank you". To connect a real backend, replace `fakeSubmit` with a `fetch` to an endpoint you own.
